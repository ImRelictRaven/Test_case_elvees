## Test_case_elvees — тестовое окружение для 16‑разрядного АЛУ

Этот репозиторий содержит упрощённый дизайн 16‑разрядного АЛУ и самописное testbench‑окружение на SystemVerilog с набором тестов.

---

## Структура проекта

- **rtl/**  
  - `top_alu_16.v` — верхнеуровневый модуль 16‑разрядного АЛУ (`alu16`), каскад из четырёх 4‑разрядных АЛУ.  
  - `74181.v` — модель классического 4‑разрядного АЛУ 74181.  
  - `74182_CLA.v` — модуль ускоренного переноса 74182 (Carry Look‑Ahead).

- **tb/**  
  - `alu_if.sv` — SystemVerilog‑интерфейс для подключения testbench к DUT.  
    - **Входы DUT**: `a`, `b`, `Cin`, `mode`, `sel`.  
    - **Выходы DUT**: `result`, `Cout`, `nBo`, `nGo`.  
    - Три modport:
      - `dut_mp` — для подключения DUT (читает входы, пишет выходы);
      - `tb_mp` — для testbench (управляет входами, наблюдает выходы);
      - `monitor_mp` — для пассивного монитора.
  - `alu_tb.sv` — основной модуль testbench:
    - экземпляр `alu_if` (`alu_intf`);
    - явное соединение интерфейса с входами/выходами DUT (`alu16`);
    - подключение монитора `alu_monitor`;
    - инклюды всех тестов из директории `tests/`;
    - счётчики пройденных/заваленных тестов и итоговый отчёт.
  - `alu_monitor.sv` — пассивный монитор:
    - подписан на `alu_if.monitor_mp`;
    - логирует изменения `result`/`Cout` и входных сигналов (`a`, `b`, `mode`, `sel`, `Cin`).

- **tests/** — набор задач‑тестов (tasks) на SystemVerilog, подключаемых в `alu_tb.sv`:
  - `alu_add_basic_test.sv` — тест операции **ADD**;
  - `alu_sub_basic_test.sv` — тест операции **SUB**;
  - `alu_shift_basic_test.sv` — тест операции **A + A** (логический сдвиг через сложение);
  - `alu_carry_only_test.sv` — тест только **наличия переноса** при сложении;
  - `alu_nocarry_only_test.sv` — тест только **отсутствия переноса** при сложении;
  - `alu_and_basic_test.sv` — тест логической операции **AND**;
  - `alu_xor_basic_test.sv` — тест логической операции **XOR**;
  - `alu_or_basic_test.sv`  — тест логической операции **OR**;
  - `alu_all_ops_3_5_test.sv` — обзорный тест по **всем комбинациям mode/sel/Cin** для фиксированных значений `A=3`, `B=5`.

- **sim_main.cpp** — минимальный C++‑wrapper для модели `Valu_tb`, генерируемой Verilator’ом:
  - инициализирует Verilator;
  - создаёт объект `Valu_tb`;
  - крутит цикл `while (!Verilated::gotFinish()) top->eval();`.

- **Makefile**

## Архитектура тестового окружения

### Интерфейс `alu_if`

- Описывает полный набор сигналов между testbench и DUT.  
- Через modport’ы:
  - DUT работает только с `dut_mp`;
  - testbench управляет сигналами через `tb_mp`;
  - монитор читает все сигналы через `monitor_mp`.

### Testbench `alu_tb`

- Инициализирует:
  - интерфейс `alu_if`;
  - DUT `alu16` из `rtl/top_alu_16.v`;
  - монитор `alu_monitor`.
- В `initial`‑блоке:
  - `initialize_test()` — сброс интерфейса и обнуление статистики;
  - `run_tests()` — последовательный вызов всех тестовых tasks;
  - `report_results()` — вывод сводки по количеству пройденных и упавших тестов, затем `$finish`.

### Монитор `alu_monitor`

- Пассивно отслеживает изменения на интерфейсе.  
- При изменении `result` или `Cout` печатает строку с текущими `mode`, `sel`, `Cin`, `a`, `b`, `result`, `Cout`.  
- Используется для удобного анализа поведения DUT и отладки тестов.

## Формат и типы тестов

Все основные тесты реализованы как **CRV‑тесты с использованием случайных входных данных**:

- **Случайные входы**:
  - `alu_add_basic_test.sv`, `alu_shift_basic_test.sv`, `alu_and_basic_test.sv` и аналогичные тесты:
    - внутри цикла генерируют пары операндов через `$urandom()[15:0]`;
    - для каждой пары вычисляют **ожидаемый результат** и, где нужно, ожидаемый `Cout`;
    - сравнивают вывод DUT (`alu_intf.result`, `alu_intf.Cout`) с ожиданием `expected`;
    - в случае расхождения печатают подробное сообщение и помечают тест как проваленный.

- **Почему не используются `assert` в тестах**:  
  В данном testbench проверка корректности результатов реализована через `if` и вывод сообщений в лог, а не через `assert`‑конструкции . Это сделано намеренно, чтобы при первой же ошибке симуляция **не останавливалась**, и могли выполниться все остальные тесты.

- **Тест на все операции `alu_all_ops_3_5_test.sv`**:
  - фиксирует входы `A_log = 3`, `B_log = 5`;
  - перебирает **все возможные комбинации**:
    - `mode` в диапазоне `0..1`,
    - `Cin` в диапазоне `0..1`,
    - `sel` в диапазоне `0..15`;
  - для каждой комбинации делает задержку `#10` и печатает в лог `mode`, `sel`, `Cin` и `result`.
  - **Назначение**: это не проверочный тест в классическом смысле, так как нет сравнения с ожиданием, а обзорный тест на отклик:
    - позволяет быстро убедиться, что DUT реагирует на все коды операций;
    - помогает визуально просмотреть поведение всех операций в одном месте.

## Список тестов

- **Обзорный тест отклика**:
  - `alu_all_ops_3_5_test.sv` — перебор всех комбинаций `mode/sel/Cin` при `A=3`, `B=5`.

- **Арифметические операции**:
  - `alu_add_basic_test.sv` — random‑тест для операции **ADD**;
  - `alu_sub_basic_test.sv` — random‑тест для операции **SUB**;
  - `alu_shift_basic_test.sv` — random‑тест для операции **A + A**.

- **Проверка переноса с критическими входными данными**:
  - `alu_carry_only_test.sv` — тестирует **наличие переноса** при сложении, фокус на `Cout`;
  - `alu_nocarry_only_test.sv` — тестирует **отсутствие переноса**, также фокус на `Cout`.

- **Логические операции (directed + random data)**:
  - `alu_and_basic_test.sv` — random‑тест для **AND**;
  - `alu_xor_basic_test.sv` — random‑тест для **XOR**;
  - `alu_or_basic_test.sv`  — random‑тест для **OR**.

Для каждого теста ведётся счётчик успешных/провальных запусков, а в конце `alu_tb` выводит суммарную статистику.

## Требования к окружению

- **Verilator**:
  - Актуальная версия Verilator.

- **C++‑компилятор**:
  - Требуется **современный C++‑компилятор с поддержкой coroutines и стандарта C++20**,
    так как в коде используются задержки и старые версии это не поддерживают.

- **Сборочные инструменты**:
  - `make`;

---

## Сборка и запуск симуляции

- **Сборка и запуск одним шагом**:

```bash
make clean
make run
```

Эта команда:
- запускает Verilator для генерации C++‑моделей из `rtl/*.v` и `tb/*.sv`;
- собирает исполняемый файл симуляции в `obj_dir/Valu_tb` с помощью выбранного C++‑компилятора;
- запускает симуляцию testbench’а `alu_tb`, выполняя все тесты по очереди.

```

После запуска в консоль выводятся:
- сообщения монитора (`alu_monitor`) о ходе вычислений;
- логи каждого отдельного теста (успех/ошибка по каждому набору данных);
- итоговый блок `=== TEST SUMMARY ===` с количеством пройденных и проваленных тестов.

---

## Интерпретация результатов

- Если все тесты пройдены:
  - в конце лога будет ноль в поле **Failed tests**;
  - обзорный тест `TEST ALL OPS (A_log=3, B_log=5)` покажет ожидаемое разнообразие откликов для разных `mode/sel/Cin`.

- Если некоторые тесты упали:
  - в логах проваленного теста будет выведен `FAILED`;
